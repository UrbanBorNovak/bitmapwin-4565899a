- Shard Raids (src/lib/shard-raid.ts): hourly shard sets are picked deterministically from inscribed Guardians; claims, mount unlocks and the one-time BIT payout go only through shard-raid.functions.ts against deny-all tables. Mount riding (guardian-mount.ts) is a movement intent, not a vehicle. Why: rewards stay server-judged while every visitor sees the same shards.
- Battle Royale (src/lib/battle-royale.ts) is wall-clock scheduled per match id and syncs joins/outs/crates over the "oasis-br" channel; it never awards BIT. Why: shared plane/storm with no server state; device-reported wins are forgeable.
- Guardian master V7 (src/lib/guardian-delegate-v7.ts) is built from the V6 source by checked string swaps plus one V7 block; V7 (#127,517,786) is the active Tag 11 delegate; V6 stays the Tag 3 root. Why: keeps the live V6 bytes untouched.
- Holder Epoch land perks (src/lib/holder-epoch.ts landBoost) come only from bitmap_index genesis + latest traced sale; they scale the daily visitor dividend and the Extender maxHeight. Why: holding is rewarded from chain facts, never browser claims.
- Land Forge (src/lib/voxel-populate.ts, /forge): builds are generated deterministically from block height + tx count, packed as BWVX1 (4 bytes/block) and reinscribed as self-rendering HTML onto the BITMAP's own sat (ShadowInscriber reinscribeOnBitmap → tag-2 pointer; parents still claimed). Resolver reads /r/sat/<sat>/at/-1 first, child crawl as fallback. Why: the inscribed bytes are the proof, no server state needed.
- Inscribed Land Forge builds are verified from the BITMAP sat's reinscriptions on ordinals.com (forge.server.ts) and cached in bitmap_forge_builds (public read, server-written); marketplace cards read only that directory. Why: cards stay cheap while the badge still comes from chain.
- Land Forge Studio (/forge, src/lib/forge-prefabs.ts): builds are composed from house prefabs + community forge_modules (public read, written only via forge-modules.functions.ts). Each module stores a flattened lineage of ancestor makers; stamping pays its BIT royalty server-side, and inscribing pays tributeSplit(lineage) as extra reveal outputs (≥546 sats, max 8). Why: creators are paid by the Bitcoin transaction itself, not by a trusted payout.
