- Shard Raids (src/lib/shard-raid.ts): hourly shard sets are picked deterministically from inscribed Guardians; claims, mount unlocks and the one-time BIT payout go only through shard-raid.functions.ts against deny-all tables. Mount riding (guardian-mount.ts) is a movement intent, not a vehicle. Why: rewards stay server-judged while every visitor sees the same shards.
- Battle Royale (src/lib/battle-royale.ts) is wall-clock scheduled per match id and syncs joins/outs/crates over the "oasis-br" channel; it never awards BIT. Why: shared plane/storm with no server state; device-reported wins are forgeable.
- Guardian master V7 (src/lib/guardian-delegate-v7.ts) is built from the V6 source by checked string swaps plus one V7 block; V7 (#127,517,786) is the active Tag 11 delegate; V6 stays the Tag 3 root. Why: keeps the live V6 bytes untouched.
- Holder Epoch land perks (src/lib/holder-epoch.ts landBoost) come only from bitmap_index genesis + latest traced sale; they scale the daily visitor dividend and the Extender maxHeight. Why: holding is rewarded from chain facts, never browser claims.
- Land Forge (src/lib/voxel-populate.ts, /forge): builds are generated deterministically from block height + tx count, packed as BWVX1 (4 bytes/block) and reinscribed as self-rendering HTML onto the BITMAP's own sat (ShadowInscriber reinscribeOnBitmap → tag-2 pointer; parents still claimed). Resolver reads /r/sat/<sat>/at/-1 first, child crawl as fallback. Why: the inscribed bytes are the proof, no server state needed.
- Inscribed Land Forge builds are verified from the BITMAP sat's reinscriptions on ordinals.com (forge.server.ts) and cached in bitmap_forge_builds (public read, server-written); marketplace cards read only that directory. Why: cards stay cheap while the badge still comes from chain.
- Land Forge Studio (/forge, src/lib/forge-prefabs.ts): builds are composed from house prefabs + community forge_modules (public read, written only via forge-modules.functions.ts). Each module stores a flattened lineage of ancestor makers; stamping pays its BIT royalty server-side, and inscribing pays tributeSplit(lineage) as extra reveal outputs (≥546 sats, max 8). Why: creators are paid by the Bitcoin transaction itself, not by a trusted payout.
- Active Builders (src/lib/forge-builders.ts) rank makers from public forge_modules only (recency + uses); avatars are deterministic from the maker address, shown on the homepage and the fog-free Oasis centre jumbotron. Why: promotion comes from published pieces, not self-claims.
- Parcel Floor Metric (src/lib/forge-parcels.ts): each canvas cell has exactly one owner (largest true Mondrian coverage, ties to lower tx index) and builds clip to owned cells; a parcel's footprint is its Mondrian rect on the 64-cell grid (min 1×1, scaled ×span/64 on XL), hard-clipped on inscribe and render; height is the full canvas ceiling regardless of footprint; a verified parcel build replaces the district build only inside its rect; the bitmapwin-parcel meta must equal the derived rect for that index. Why: tile rights come purely from block math, micro-parcels stay usable, and any viewer re-derives the same bounds.
- Parcel holders reinscribe onto their own parcel sat (mintParentsFn parcelIndex, live holder from parcelHoldersFor); forgeLandFor reads each parcel sat's newest bitmapwin-parcel build, which overrides the district build inside that tile in ForgeBuild3D. Why: tile rights come from the chain, never the browser.
- Guardian visuals (src/lib/onchain-guardian.ts) are a port of the on-chain World++ voxel blueprint fed by morphFromDna; GuardianBody, GuardianPortrait and the Command Centre Guardian Index all use it. Why: one inscription-identical look everywhere.
- Recursive assemblies support an XL 128³ canvas via data-span="128" (own blocks always BWVX2, drawn at half block size on the same land); no tag = original 64³. Why: old inscriptions never change meaning.
- Recursive assemblies (src/lib/forge-assembly.ts, BWVX_ASM): inscribed pieces are referenced by inscription id + placement and fetched live by the inscription (/r/metadata, fallback /content); only own blocks and an optional baked Guardian blueprint (forge-guardian-bake.ts) are stored. forge.server.ts flattens them for the Oasis. Why: reused pieces are never paid for twice.
- Guardian breeding (src/lib/guardian-genetics.ts): pets are a pure crossover seeded by sire+dam inscription ids; only inscribed Guardians may be parents and the pet inscription carries both ids in metadata. Why: any client can re-derive and verify a pedigree.
- Pet Master Delegate (src/lib/pet-delegate.ts): lean pets inscribe an empty body + Tag 11 to the master and carry baked voxels in Tag 5; holders can claim their held Guardian as Tag 3 parent (heldParentSpendFn, wallet-signed pass-through). Why: cheapest pets with official on-chain pedigree.
- Emporium residency (src/lib/emporium.server.ts) is verified live on ordinals.com: image children of 717328.bitmap at the address (/r/parents + /r/inscription address) or valid 717328 parcels; the Passport stamp stores the proving inscription id. Why: residency comes only from chain.
- Community kits (src/lib/kit-packager.ts, community-kits.functions.ts): canvas builds are auto-sliced bottom-up into numbered bags; publishing requires a mempool-seen tx paying KIT_PUBLISH_SATS to DONATION_ADDRESS from the maker's wallet, one kit per txid, server-written to community_kits (public read). Why: the fee is proven by Bitcoin, not browser claims.
- District Parcel Foundry (src/lib/parcel-foundry.ts, /kennels): one deterministic Outpost per transaction parcel, derived from (height, index) and clipped to the parcel's exclusive Mondrian cells; placed via Land Forge (?parcel=). Legacy kennel tables/functions stay untouched but unused by the UI. Why: parcel pieces follow Bitmap tile rights and need no server state.
- Inscribed Worlds (src/lib/inscribed-world*.ts): Inscribed.space / recursive 3D HTML worlds are detected live from a BITMAP's sat reinscriptions and children on ordinals.com and run unmodified in a scripts-only sandboxed iframe of /content/<id>; no database index (directory scans in batches). Why: the creator's own engine keeps full fidelity and the chain stays the only proof.
- Inscribed World geometry bridge (src/lib/inscribed-world-bridge.ts): Oasis draws the world's on-chain worldData — box/plane primitives plus its placed Draco glTF models loaded live from ordinals.com/content by inscription id — fitted to the building cluster (floor planes and far markers ignored) and clipped to the BITMAP. Why: the creator's own on-chain models are shown, never re-hosted.
- Inscribed Worlds may also anchor by output value === height (src/lib/inscribed-world-anchors.ts), re-checked live each lookup. Why: some creators name the BITMAP via postage instead of Tag 3; this is an app convention, not parentage.
- Inscribed.space Archive (src/lib/inscribed-space-archive.ts, vendor/inscribedspace-archive.json): the 87 ordengine/inscribedspace_backup builds are vendored server-side and used only when a BITMAP has no live on-chain Inscribed.space world; only ordinals.com models are kept and the build is labelled ARCHIVE, never parentage. Why: instant, rate-limit-free loading while the chain stays the first source.
- OCI sat cache (bitmap-oci.server.ts) follows LiveOCI v1.1: pages to 969,999 plus OCI_ID_FIXES (oci-fixes.ts) which win over raw pages; heights ≥970,000 resolve live from blocks. Why: match the canonical on-chain index byte-for-byte.
- Inscribed.space archive lives in Archaeology (src/lib/vendor/inscribed-spaces-catalog.json), never in the Oasis; links go to ordinals.com. Why: history without loading foreign worlds into the shared map.
- Wildlife and VoxelTrees spawn by wildBiomeAt (src/lib/wild-biome.ts); far critters relocate near the visitor and re-pick species for that biome. Why: nature matches the ground anywhere.
- District Fiefdom: runDailyRewards pays FIEF_SPLIT of each visited BITMAP's visitor BIT pro-rata to valid on-chain parcel holders via parcelHoldersFor (src/lib/parcel-fief.server.ts, first claim per tx index, live holder). Why: parcel shares come only from chain scans, never browser claims.
- Oasis voxels (src/lib/voxel-world.ts): only edits render; place/break/gather/craft go through security-definer voxel_edit/voxel_harvest/voxel_craft against server-held voxel_bags (deny-all), synced live on "oasis-voxels". Why: blocks cost resources that browsers cannot forge.
- Sovereign Store (src/lib/sovereign-store.ts, nostr-listing.ts): listings are kind-30402 Nostr events carrying the seller-signed SINGLE|ACP PSBT; the shop re-checks each on chain (unspent, inscription in UTXO, LiveOCI canonical id) and builds the buyer swap in-page with two buyer padding inputs so the seller input/output sit at index 2 and the BITMAP lands at output 1. Why: no BitmapWin server is needed, and the Nostr key is only a messenger.
- Marketplace purchases (psbt-buyer.ts buildBuyerPsbt) put two buyer padding coins first so the seller input/price output sit at SELLER_INDEX 2 and the BITMAP lands at output 1; submitPurchase refuses to broadcast unless satDestination proves that. Why: sats flow first-in first-out, and the old index-0 layout sent the BITMAP back to the seller.
- Co-Forge (src/lib/co-forge.ts, /co-forge): multiplayer BWVX_ASM rooms sync tiny LWW ops (piece-by-id or loose block) over Nostr kind 7417 tagged bitmapwin-coforge:<room>; pieces load from chain, export is forgeAssemblyHtml downloaded only. Why: no server state, and moving a whole piece costs one small event.
