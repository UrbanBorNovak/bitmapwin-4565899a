- Biternam interiors (/biternam/museum, /biternam/cafe, /biternam/outpost) are fixed-camera R3F rooms; picking uses client/rect ratios (zoomSafeEvents) and quest progress goes only through questStore. Why: page-size CSS zoom skews default R3F picking; one store keeps Oasis and interiors in sync.
- Cinematic Director (src/lib/cutscene.ts + CutsceneDirector.tsx): room cutscenes are screen-space keyframes (CSS push-in, letterbox, light, subtitles) played by HideoutShell on gain/solve; picking is disabled while playing. Why: no camera rewiring per room and CSS transforms don't resize SafeCanvas.
- Toon stage collisions (src/lib/toon-collide.ts): cast are circles that separate each frame (earlier slots keep their mark) and are pushed out of set footprints (footprintsFor); extras refuse steps into any character. Why: no character ever overlaps another or a voxel object.
- Gear Locker (src/lib/biternam-gear.ts): each interior parks one Oasis on-chain ride (OnChainExhibit, loaded live from ordinals.com) and a GearShelf of three Oasis wearables drawn via InscribedModel (shared flattened geometry, inspect-only); clicking salvages one part per room and parts combine via fixed RECIPES. Device-local, pays no BIT. Why: reuse the inscribed models without new server state.
- Backrooms (src/lib/biternam-backroom.ts): /biternam/vault and /biternam/lair are sealed by a Shadow Vault pass whose fingerprint is registered by claimBackroomPassFn only after the earning room is solved server-side; biternam_backroom_claims (deny-all) limits one per account and never stores the fingerprint. Backroom events stay is_active=false so the public pass claim refuses them. Backroom take/use steps are protected actions: recordHideoutStep re-checks the pass (shadow_verify_pass) on every step, signed-out play and device storage never advance them; scenes, look and talk stay public. Why: entry is proven by the device-held pass, and hiding the door in the browser grants nothing.
- Backstage VIP Lounge (/biternam/lounge): opens only after enterLoungeFn verifies a BIP-322 signature from a wallet already in launch_seats; it writes nothing and grants no BIT, and the device keeps the opened seat for the tab session. Why: seat holders prove themselves by key, never by a browser claim.
